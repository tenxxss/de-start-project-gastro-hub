Gastro Hub — аналитика сети ресторанов на PostgreSQL
Модель данных

Схема cafe, 4 таблицы:

restaurants — заведения: cafe_name, тип (coffee_shop / restaurant / bar / pizzeria через ENUM), меню в jsonb.
managers — управляющие заведениями.
restaurant_manager_work_dates — связующая таблица «кто каким заведением управлял и в какой период» (составной первичный ключ + диапазон дат).
sales — ежедневная выручка (средний чек) по каждому заведению.

Использованы uuid как первичные ключи, ENUM-тип для категорий заведений, jsonb для гибкого хранения меню — то есть не только базовые CREATE TABLE, а осознанный выбор типов данных под задачу.

Аналитические запросы

Часть решённых задач:

Топ-3 заведения по среднему чеку в каждой категории — оконная функция ROW_NUMBER() OVER (PARTITION BY type ORDER BY avg_check DESC), обёрнутая в CREATE VIEW.
Изменение среднего чека год к году — LAG() для сравнения с предыдущим периодом, финальный расчёт процента изменения, результат сохранён как MATERIALIZED VIEW (учтено, что представление можно переиспользовать без пересчёта на лету).

Остальные задачи (task_3–task_7) — дополнительные аналитические выборки по той же модели данных (JOIN, агрегатные функции, условная логика).

Технологии

PostgreSQL: DDL с ENUM/JSONB/UUID, CTE, оконные функции (ROW_NUMBER, LAG), VIEW и MATERIALIZED VIEW.

Структура репозитория
DDL.sql — создание схемы и таблиц.
INSERT.sql — наполнение тестовыми данными.
task_1.sql – task_7.sql — решения по задачам.
comments.txt — комментарии к решению.

Как запустить
Выполнить по порядку в PostgreSQL: DDL.sql → INSERT.sql → любой из task_*.sql.
